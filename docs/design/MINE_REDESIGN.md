## 0. 背景与硬约束

- 目标:**基于工程中心框架完全重设计挖矿模块**(第一版工程设计草案作废)
- ✅ **矿井生成算法不能改**:`SpiralMinePlanner` 及周期/层坐标计算(`computeCycle` 风格的 keeps/lights 计算)原样搬迁,只移动不修改任何坐标公式
- ✅ 挖矿分两条线:
  - **矿井挖矿**(Home 模式):逐步完成矿井建造,走工程中心流程
  - **跟随采矿**(跟随模式):只采掘跟随范围内的表面矿,纯 Behavior,**逻辑独立于矿井**(不是砍树那种拦截气泡,真的能干活的)

## 1. 架构:矿井 = 工程中心子类

✅ 用户拍板:**矿井方块 = 工程中心方块的子类实现,完全走工程中心这一套**

```
ProjectCenterBlock        ← MineBlock(子类方块)
ProjectCenterBlockEntity  ← MineBlockEntity(身份桥 + 容器)
ProjectCenterInstance     ← MineInstance(后台实例,SavedData 持久化)
ProjectCenterManager      ← 能同时驱动两类实例
```

差异点(子类覆写):

| 维度 | 普通中心 | 矿井(子类) |
|---|---|---|
| 几何 | 半径立方体(radius+anchor) | 标记工具两角点 + 奇数边长 |
| 目标来源 | 方块扫描(stateFilter) | 螺旋规划器按周期/层生成任务 |
| 任务模型 | 块目标(原木) | (坐标, DIG/FILL/LIGHT/REPLACE) 四类 |
| 创建流程 | 直接放方块 + 激活面板选类型 | 标记工具选角点 → 确认 → 放矿井方块(类型固定"采矿",无激活面板) |
| 附加能力 | 通用临时仓库 + 困难任务表(A1 拍板,升级为全中心通用,不限格数) | 竖井形状参数 + 螺旋分层(仓库/困难表已上移为通用,见 A1) |

✅ **已拍板(2026-09-04):矿井 = 工程中心子类,复用同一套管理器 + 多态 Codec 分派**
- 工程中心(基类)保持**通用/解耦**:半径区域、存档、每 tick 驱动、给女仆分活、清理。`ProjectCenterManager` 零改动(本就是按基类泛型遍历),仅新增 `createMine` 入口。
- `ProjectCenterInstance` 长期运行,只靠**多态 Codec** 区分"普通中心 / 矿井"(照抄 `ProjectBase.CODEC` 的 `Codec.STRING.dispatch(kind→...)`),旧存档回落 "center"。
- 分界:**通用架子**(存档/派活/清理/区域/仓库/困难表)→ 基类复用;**矿井特有**(竖井构造 + 跟女仆挖矿行为的耦合)→ 子类。

**三条子决定(均已确认):**
1. **区域语义**:中心 `半径+锚点` = 干活边界(挖掘行为只在范围内发生),与伐木中心**完全同义**,照旧复用;**竖井形状参数**(标记工具两角点/螺旋尺寸)不是中心参数,属矿井子类,用于构造竖井(换形状如倒锥则随之改)。
2. **储物 → 通用**:推进工程中心,担任"工程临时仓库";**不限 27 格**,改做面板数据记录(所有中心共享,非矿井专属)。
3. **困难任务表 → 通用**:放入工程中心,因任何工程都可能遇到"当前工具挖不动、留待处理"的情况。

**层级:**
```
ProjectCenterInstance(基类,通用/解耦: 半径+存档+分活+仓库+困难表)
   └── MineInstance(子类,与女仆挖矿行为耦合: 竖井形状参数 + 螺旋分层 + 四类坐标任务 + 索光源/结算中介)
```

## 2. 几何分离 + 深度限制

✅ 用户拍板:矿井边长和工程中心范围**分开处理**(为鱼骨矿道预留)

- **螺旋 L/W**:标记工具两角点定(奇数、`≥7` 下限,与普通中心 `2r+1` 恒奇数同一套几何约束),只喂 `SpiralMinePlanner`
- **强制正方形**(2026-09-04 测试补充拍板):竖井长宽必须一致,两角点框选非正方形时**自动按长边取正、以框选中点居中**;确认窗提示"已按长边取正方形"
- **中心半径/基准点**:独立可编辑(EditHUD 里调),默认覆盖矿区 + 鱼骨预留(实际边长 = 矿井边长 + 两边鱼骨矿道最长距离)
- **深度限制 = 中心盒子底**(anchor=top 时 `y - 2r`):螺旋下挖到该 Y 即"挖到底",停止派发新层

## 3. 工程位 = 一层

✅ 用户拍板:挖矿的工程位是"**一层**",派发时直接把一层的区域范围做成一个 project 创建

```
矿井实例(中心子类)持有一层工程
└─ 当前层 → MiningProject(多人参与,实时破坏方块,非计数型)
   ├─ 任务池:该层所有需处理坐标(区域 ±1 圈)
   ├─ 派发:女仆请求推进 → 无子任务 → 取距她最近未处理坐标 → 判定类型
   │        (挖掘/补充/替换;keep 完好 → 直接跳过不生成子任务)
   ├─ 子任务:女仆 ↔ 单个坐标绑定,完成前不接新任务
   ├─ 离场:子任务取消,坐标退还池子
   └─ 池子空但子任务进行中 → 其他无任务女仆请求 → 让位等待
完成后 → 矿井推进下一层 → 新建层工程
```

- ✅ 该层工程属于**实时更新类型**:完成前不仅更新后台进度,方块也要实际破坏

## 4. 任务四型

✅ 用户拍板:REPLACE 概念保留,四类任务都要真正派发

- **DESTROY / FILL / REPLACE / SETLIGHT** 四类
- 旧代码事实:REPLACE 和 LIGHT 只算了集合(`currentCycleReplaces`/`currentCycleLights`),任务扫描只当排除项,分支从未真正生成任务 → 僵尸设计。新设计全部真正派发
- ✅ 处理顺序:**保留 → 挖掘 → 补充 → 光源**(用户纠正了旧 TODO 的"光源→替换→保留→挖掘")
- 旧的 `currentCycleReplaces`(内圈一周独立集合)概念**作废**;REPLACE 改为任何 keep 位遇到非垫脚实体块时**按需生成**

## 5. REPLACE = 墙壁处理

✅ 用户拍板:REPLACE 的用途是**处理墙壁**

keep 位(墙壁/踏步)必须是"实体垫脚方块",三态处理:

| keep 位状态 | 处理 | 原因 |
|---|---|---|
| 空气/空洞 | FILL 补上 | 防怪物穿墙、防流体漏进矿道 |
| 已是垫脚方块 | 跳过(丢已处理) | 无需处理 |
| 非垫脚实体方块(石头/矿石) | REPLACE 挖掉再垫 | 防玩家看着墙上留矿难受,顺带回收墙上矿 |

## 6. 派发树(唯一真相)

✅ 用户 [if] 编号原文,逐条确认过:

```
女仆请求推进(无绑定子任务时):
  0. 先过困难列表:矿井困难表 → 层工程困难表,有能处理的 → 取走干活
  1. 未处理列表非空 → 取最近坐标 → 在保留列表?
     ├─ 在:无方块 → FILL
     │    有方块 → 垫脚 → 丢已处理,等下次请求
     │             非垫脚 → 能处理?→ 是 → REPLACE 派发
     │                              → 否 → 层困难表,等下次请求
     └─ 不在:能处理?→ 是 → DESTROY 派发
                         → 否 → 层困难表,等下次请求
  2. 未处理空 → 光源列表非空?
     ├─ 有:女仆有光源 → 取最近 → SETLIGHT 派发
     │     无光源 → 跳出,Behavior 驱动她去矿井方块索要
     └─ 空:工程结束 → 有子任务进行中 → 等
                     → 无 → 结算:层困难表上缴矿井,删工程,矿井派发新层工程
```

各工程持有:**子任务列表 / 保留列表 / 未处理列表 / 已处理列表 / 光源位置列表**。

### B1 拍板（2026-09-04）：女仆侧 Home 循环

- 女仆侧新增**专用挖矿 Behavior**(Home 模式下与矿井中心对接),不复用砍树"一次性给全目标/计数"模型
- 循环:女仆空闲 → 向矿井中心要活 → **中心**从当前层任务池挑**距她最近的未占用坐标**、按类型(挖/填/替换/光源)派发 → 女仆装备最好的镐 → 寻路 → 执行 → 完成后再要下一坐标 → 循环 → 整层完成 → 中心结算、推进下一层
- **由中心决定"下一个坐标"**:`MineInstance` 对外只开一个"派活"口(返回"坐标 + 动作类型"或"本层无活"),女仆只与此口交互;螺旋算法/分层/结算全在中心内部(对应上方派发树的就近分配)
- 特殊情况:工具不足 → 该坐标进困难表、换下一格;要放灯但无光源 → 先去中心仓库取;背包满 → 先把矿存进中心仓库再继续
- 本质为**逐坐标执行型**工程(真实破坏/放置),非 CountingProject 计数型
- 落地说明(2026-09-04 实现批次):层任务池暂由 `MineInstance` 直接承载(周期/层索引持久化,层池重载后按周期重算,实时方块状态即进度真相);`MiningProject`(ProjectBase 包装)随女仆行为批次落地

## 7. 困难任务双层结构 + 红点渲染

✅ 用户拍板:

- **层工程困难表**:独立于常规工程子任务的特殊处理;DESTROY/REPLACE 被拒时入表(无法破坏 / 工具等级不够);女仆申请新子任务时**优先**从该表查找,能处理就取走
- **矿井困难表**:层结算时上缴累积;女仆请求任务时**先于一切**过一遍工程中心(矿井)困难表
- 若工程所有可用子任务派发完,困难表仍有无法解决/难以解决的子任务 → 推送到工程中心
- **红点渲染**:玩家手持标记工具且标记工具绑定了该矿井时,矿井困难表所有位置方块标红(客户端渲染)

## 8. 难度判定 — 纯布尔

✅ 用户拍板:不需要分级,只有"能做/不能做"一个 bool

```
不能做 = destroySpeed < 0(基岩类)                 ← 永远不能
     或 方块 requiresCorrectToolForDrops
        且 女仆主手工具 isCorrectToolForDrops == false   ← 铁镐挖黑曜石 → false
其余 → 能做
```

- 女仆开工前先装备最好的镐(复用砍树 `equipAxe` 模式),然后用主手工具判定

## 9. keep 位流体

✅ 用户拍板:

- **源流体**(`state.isSource()`)→ **REPLACE**:setBlock 空气清掉 + 生成对应流体瓶塞(复用旧 `checkBelowSafety` 流体瓶逻辑 + `FluidBottleItem.setFluid`),再垫垫脚方块
- **非源流体**(流动水/岩浆)→ **FILL**:直接在上面放垫脚方块(setBlock 会顶掉流动流体)

## 10. 光源位

✅ 用户拍板：

- 光源位**不进未处理列表**(避免先被 DESTROY 挖了),层末尾 SETLIGHT 阶段单独派发
- 光源位有方块也不进 DESTROY 流程

### 光源位置拍板（2026-09-04 测试修正）

- 光源**只在每条边中段的 3×2 平台**处放,每平台 2 盏(每周期 4 边×2=8 盏):
  - **灯1** = 平台中柱走廊侧外一格,贴平台侧面(平台=保留区,支撑永久)
  - **灯2** = 平台端柱上方**三格(y+3)**,贴边界围墙内面(围墙=保留区,支撑永久;高于墙区的平台跳过灯2)
- **灯位保护**:发光且非流体的方块一格**永不进挖掘池**(防任意层级误挖)
- 旧方案(每层过道行放灯)**作废**:灯踩着的支撑方块属于下层挖掘区,下层一挖支撑没了灯就掉

### B2 拍板（2026-09-04）：索要光源

- **触发**:女仆领到 SETLIGHT 任务、背包无可放置光源时,先去中心取灯(不提前囤灯,不白跑)
- **领取量**:一次取**一组(或 10 个)**防来回跑;仓库不足时**有多少拿多少**(如剩 3 个就拿 3 个);仅当**一个都没有**才判定"取不到"
- **领取方式**:全自动——寻路至矿井方块旁 → 向中心请求 → 仓库扣光源入背包 → 返回坐标放置,无需玩家确认
- **仓库无光源**:女仆发出请求并在工程中心旁**阻塞等待**("发出请求"属后续规划,现阶段以**聊天栏输出提示**替代)
- **光源判定**:任何**可放置且发光**的物品(火把/灯笼/萤石等),仓库有什么用什么

### B3 拍板（2026-09-04）：仓库存取协议

- **存矿触发(测试修正 2026-09-04)**:背包范围**仅背包格**(左手完全不参与,不计数不填充);流程 = 干完手头这格活 → **产物放入背包** → 检查放入后**无空格** → 立即前往仓库存放(到仓时全满为正常);寻路连续失败 3 次 → 气泡提示 + 放弃本次存货继续干活(多余掉落落地),不死等
- **存什么(黑名单制,修正)**:镐/垫脚/光源不存;**流体瓶为填充流体的产物,正常入库**;黑名单外全部入仓
- **存取实现**:统一走合并容器(availableBackpackInv)读写,避免"遍历基础背包看不到扩展背包产物"的站桩问题
- **取消耗品**:垫脚方块与光源走**同一套领取协议**——一次取一组(或 10 个),有多少拿多少,一个都没有则阻塞等待 + 聊天栏提示(同 B2)
- **玩家面板存取**:留到 UI 阶段;本次只定数据协议——仓库 = 中心持有的一张物品列表,支持女仆存取 + 玩家面板存取

### C1 拍板（2026-09-04）：跟随范围与矿石判定

- **范围模型**:跟着玩家走、**沿途见矿就挖**(检索以她沿途所及为准);**距玩家超过一定距离(可配置,默认值实现阶段定)→ 直接中断当前挖矿任务、归队跟上**。距离锚点是**玩家**,不是固定搜索半径
- **矿石判定三条件(先按此实现)**:
  1. 矿石标签(tag,数据驱动,兼容模组矿)
  2. 至少一面邻空气(露天,不隔墙挖)
  3. §8 难度布尔(基岩类不挖;需正确工具而手中工具不行不挖)
- **占用跳过**:已被认领的坐标(其他女仆/工程)直接跳过,复用占用快照 `collectOccupied`

### C2 拍板（2026-09-04）：采集流程与背包满策略

- **采集流程复用**:提取"**单坐标执行**"公共例程(寻路到旁 → 装备包里最好的镐 → 挖 → 掉落物进背包),Home 挖矿与跟随采矿**共用同一实现**,不写第三份"挖一格"
- **背包满策略(可配置)**:提供配置项由玩家决定"背包满 → 停止挖矿纯跟随"还是"继续挖";**默认 = 停止**(停止检索新矿、不再挖,背包有空位后自动恢复)
- **不扔地上、不找仓库存**:跟随模式独立于矿井,不与仓库耦合
- **超距归队被打断的矿**:不做特殊处理——仍是露天未占用矿石,下次路过再次检索到即接着挖

## 15. D 组拍板（2026-09-04）

### D1:重力方块掉落 — 纳入,层内周期**全量**重扫

- 当前层每隔一段时间(间隔可配置)对**当前层全区域**做一次重校验,任何与规划预期不符的坐标重新入队:
  - 多出来的方块(掉进矿道的沙/沙砾等) → DESTROY
  - 缺失/不对的保留位 → FILL / REPLACE
